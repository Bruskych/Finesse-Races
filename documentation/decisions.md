## D001 - Выбор версии Minecraft
Дата: 18.09.2026
Статус: Принято

### Проблема
Необходимо выбрать версию Minecraft для разработки мода.

### Рассмотренные варианты
- Minecraft 1.20.1
- Minecraft 1.21.1

### Принятое решение
Для проекта выбрана версия Minecraft 1.20.1.

### Обоснование
Хотя версия 1.21.1 считается более современной и популярной, мой модпак разрабатывается и поддерживается именно на версии 1.20.1. Кроме того, для 1.20.1 доступно гораздо больше интересных модификаций, любимых сообществом.

## D003 - Выбор метода масштабирования GUI
Дата: 20.09.2026
Статус: Принято

### Проблема
Необходимо выбрать способ масштабирования / отрисовки графического окна интерфейса, чтобы можно было изменять его ширину и высоту без ухудшения внешнего вида.

### Рассмотренные варианты
* Единая текстура одного размера
* Обычное масштабирование всей текстуры
* Nine-Slice Scaling

### Принятое решение
Для проекта выбран метод Nine-Slice Scaling.

### Обоснование
Выбран метод Nine-Slice Scaling, так как он позволяет изменять размер окна GUI без заметного искажения его углов и границ. Текстура разделяется на девять частей: углы сохраняют свой размер, а остальные части растягиваются в зависимости от размера окна. Благодаря этому одну текстуру можно использовать для окон разных размеров, что упрощает разработку интерфейса и позволяет изменять его размер без создания нескольких отдельных текстур.

## D004 - Выбор контейнерной системы GUI

Дата: 21.09.2026
Статус: Принято

### Проблема
- В процессе разработки GUI было обнаружено, что используемый подход с отрисовкой текстур и методом Nine-Slice Scaling представляет элементы интерфейса только как отдельные графические изображения. Такой подход позволяет изменять размер визуальных панелей, но не создаёт полноценной структуры GUI, внутри которой можно удобно размещать и управлять кнопками, текстом и другими элементами.
- Необходимо было выбрать способ организации интерфейса, при котором панели будут выступать в качестве контейнеров для дочерних элементов, а не только как фоновые изображения.

### Рассмотренные варианты
- Отрисовка текстур и элементов непосредственно в `Screen`
- Использование отдельных координат для каждого элемента интерфейса
- Создание собственных GUI-контейнеров (`GuiPanel`) для группировки элементов

### Принятое решение
Для проекта выбрана контейнерная система GUI с использованием собственного класса `GuiPanel`.

### Обоснование
- `GuiPanel` позволяет представить визуальную панель как отдельный объект интерфейса, содержащий дочерние элементы, такие как текст, кнопки и изображения. Координаты дочерних элементов могут задаваться относительно панели, благодаря чему они перемещаются вместе с ней при изменении её положения или размера.
- При этом Nine-Slice Scaling продолжает использоваться для отрисовки самой панели, но теперь отвечает только за её визуальное представление. Логическая структура интерфейса отделяется от процесса отрисовки текстуры.
- Такой подход позволяет разделить GUI на независимые компоненты и упростить дальнейшее расширение интерфейса. Например, экран выбора расы может состоять из нескольких `GuiPanel`, каждый из которых содержит собственный набор элементов.
